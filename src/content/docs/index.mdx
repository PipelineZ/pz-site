## Why pz

<CardGrid stagger>
	<Card title="SQL is the pipeline" icon="pencil">
		Transformations, reads, and writes are declared in the SQL you already
		write — `pz` compiles them into a DAG, no orchestration code.
	</Card>
	<Card title="DuckDB as the hub" icon="rocket">
		Sources land into a local DuckDB staging database, pipelines transform
		inside it, sinks drain results out — fast and in-process.
	</Card>
	<Card title="Incremental by declaration" icon="approve-check">
		`where cursor > {'{{ watermark(s, e) }}'}` is the whole incremental
		story: watermarks, bounded windows, retries, and CDC built in.
	</Card>
	<Card title="Honest delivery guarantees" icon="open-book">
		Merge and replace are effectively-once; append is at-least-once and the
		compiler makes you say so. Start with the book to see why that matters.
	</Card>
</CardGrid>
