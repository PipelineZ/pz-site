<span class="pz-kicker">The whole project</span>
## SQL files and one YAML file

A pipeline is the SQL you would write anyway. `source()` reads an entity,
`sink()` writes one, `ref()` chains pipelines — and those template calls are
what `pz` compiles into a dependency-ordered DAG. No orchestration code, no
DSL, no scheduler config.

<div class="pz-cols">

```sql title="pipelines/orders_enriched.sql"
INSERT INTO {{ sink('lake', 'orders_curated',
                    strategy: 'replace', format: 'parquet') }}
select
    o.id,
    o.amount,
    c.email
from {{ ref('stg_orders') }} as o
join {{ source('raw', 'customers') }} as c
  on c.id = o.customer_id
```

```yaml title="connections.yml"
raw:
  connector: localfiles
  entities:
    customers:
      read:
        path: data/customers.csv
        format: csv

lake:
  connector: localfiles
  root: out   # writes land under out/<entity>/
```

<span class="pz-kicker">Architecture</span>
## DuckDB is the hub

Sources land data into a local DuckDB staging database, SQL pipelines
transform inside it, sinks drain the results out. Data moves as zero-copy
Arrow batches — or never enters .NET at all when a connector can hand DuckDB
a native scan.

<div class="pz-section">
<span class="pz-kicker">Why pz</span>
## Small. Fast. Simple. Anywhere.

Not a platform, not a control plane — a CLI you install in a minute, run
the same everywhere, and actually understand.

<div class="pz-bento">
	<div class="pz-tile" style="--pz-card: var(--pz-green)">
		<p class="pz-tile-title"><i></i>Small</p>
		<p>One binary and a project folder. No web server, no metadata
		database, no worker fleet, no agents to babysit. Everything a run
		produces sits in `.pz/` next to your SQL — delete the folder and pz
		is gone without a trace.</p>
		<code class="pz-proof">$ <b>dotnet tool install</b> --global Pz.Cli</code>
	</div>
	<div class="pz-tile" style="--pz-card: var(--pz-sky)">
		<p class="pz-tile-title"><i></i>Simple</p>
		<p>A pipeline is SQL plus one YAML file. The dependency graph is read
		from the SQL you already wrote — no DSL, no DAG files, no wiring.</p>
		<code class="pz-proof">from <b>{'{{ ref(\'stg_orders\') }}'}</b></code>
	</div>
	<div class="pz-tile" style="--pz-card: var(--pz-blue)">
		<p class="pz-tile-title"><i></i>Fast</p>
		<p>An embedded analytical engine does the heavy lifting in-process,
		and data moves in zero-copy batches. Node times are milliseconds, not
		minutes of cluster spin-up.</p>
		<code class="pz-proof"><b>ok</b> orders_enriched 3 rows 23ms</code>
	</div>
	<div class="pz-tile" style="--pz-card: var(--pz-peach)">
		<p class="pz-tile-title"><i></i>Anywhere</p>
		<p>Laptop, VM, Docker, Kubernetes — Linux, macOS, or Windows. Same
		binary, same behavior, same output. Watermarks and run state can live
		in a database when the host is ephemeral.</p>
		<code class="pz-proof">$ pz run --all  <b># laptop · VM · Docker · K8s</b></code>
	</div>
	<div class="pz-tile" style="--pz-card: var(--pz-red)">
		<p class="pz-tile-title"><i></i>Simple is not sloppy</p>
		<p>A plan that can silently duplicate rows is a compile error, not a
		wiki footnote. Watermarks advance only after every sink commits, and
		`pz retry` resumes instead of redoing finished work.</p>
		<code class="pz-proof"><b>error PZ0214:</b> append fed by an incremental dataset — a replayed slice can duplicate rows</code>
	</div>
	<div class="pz-tile" style="--pz-card: var(--pz-teal)">
		<p class="pz-tile-title"><i></i>Tells you what it did</p>
		<p>Every run emits a stable, diffable NDJSON event stream, OpenTelemetry
		traces and metrics, and a `run_results.json` artifact — the same
		contract on your laptop and in CI.</p>
		<code class="pz-proof">{'{'}"event":<b>"run_completed"</b>,"status":"success","succeeded":12{'}'}</code>
	</div>

<div class="pz-section">
<span class="pz-kicker">Quickstart</span>
## Running in five minutes

<Steps>

1. Install the CLI as a .NET global tool:

   ```console
   $ dotnet tool install --global Pz.Cli --prerelease
   ```

2. Scaffold a small, complete, runnable project:

   ```console
   $ pz init demo && cd demo
   ```

3. Run both flows — sources, pipelines, checks, and sinks in one command:

   ```console
   $ pz run --all
   ```

</Steps>
