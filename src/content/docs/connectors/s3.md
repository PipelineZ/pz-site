The `s3` connector reads and writes Amazon S3 through DuckDB's `httpfs` extension. Every read
compiles to `read_parquet`/`read_csv`/`read_json` and every write to a native `COPY … TO 's3://…'`,
so data never passes through .NET. There is no universal-tier fallback: this connector is
native-only in both directions.

## Connection

```yaml title="connections.yml"
lake:
  connector: s3
  access_key: ${AWS_ACCESS_KEY_ID}
  secret_key: ${AWS_SECRET_ACCESS_KEY}
  root: my-bucket/exports
  region: us-east-1
```

| Key | Required | Default | Meaning |
|---|---|---|---|
| `access_key` | Yes | — | AWS access key id. |
| `secret_key` | Yes | — | AWS secret access key. |
| `root` | No | — | `bucket` or `bucket/prefix`. Fills the bucket and path prefix for every entity that omits its own `bucket`/`path`. |
| `region` | No | `us-east-1` | AWS region for the scoped DuckDB secret. |
| `endpoint` | No | AWS's own endpoint | Override host, for an S3-compatible store (for example MinIO). |
| `url_style` | No | `vhost` | `vhost` or `path`. |
| `use_ssl` | No | `true` | Whether requests use HTTPS. |

## Read options

Shared keys (`columns`, `sync`, `retry` under `read:`, and `rate_limit` on the connection) are
documented in [connections.yml reference](/reference/connections-yml/).

| Key | Meaning |
|---|---|
| `bucket` | Object bucket. Defaults to the connection's `root` bucket. An entity naming its own bucket does not inherit the root's prefix. |
| `path` | Object key, relative to the resolved prefix. Defaults to `<entity>.<format>`. Supports globs and calendar tokens (see below). |
| `format` | `csv`, `parquet`, or `json`. Defaults to `parquet`. |
| `columns` | Column-to-type contract. With no contract, csv/json auto-detect their schema; declaring one prunes the scan to just those columns. |

A `path` with calendar tokens narrows a windowed or incremental read to the watermark's cover
instead of scanning every object under the prefix. See [Path templating](#path-templating)
below.

```yaml title="connections.yml"
lake:
  connector: s3
  access_key: ${AWS_ACCESS_KEY_ID}
  secret_key: ${AWS_SECRET_ACCESS_KEY}
  root: my-bucket
  entities:
    events:
      read:
        path: raw/events/{yyyy}/{MM}/{dd}/*.parquet
        sync:
          mode: incremental
          cursor: event_time
```

## Write options

| Key | Required | Default | Meaning |
|---|---|---|---|
| `bucket` | No | The connection's `root` bucket | Destination bucket. |
| `path` | No | `""` | Destination prefix, relative to the resolved root. |
| `format` | Yes | — | `csv`, `parquet`, or `json`. No default: every write must declare it. |

Only `strategy: append` and `strategy: replace` are supported; there is no `merge` for an object
store. `replace` writes one stable object named `<entity>.<format>`; `append` writes a new,
uniquely-named object per run so repeated runs accumulate objects rather than overwrite one.

`partition_by` is not available on this connector: writes go only through the native `COPY` path,
which has no per-row fan-out. A single run writes to a single object or prefix.

### Path templating

`path` accepts the calendar tokens `{yyyy}`, `{yy}`, `{MM}`, `{dd}`, `{HH}`, `{mm}`, which must
appear coarse to fine with no gaps (for example `{yyyy}/{MM}/{dd}`, never `{MM}/{yyyy}`). On a
read, pz uses them only to narrow a windowed or incremental entity to the smallest set of objects
that covers the watermark window, so a query never rescans objects outside it.

## Capabilities

| Flag | Meaning |
|---|---|
| `NativeScan` | Reads compile to a native DuckDB scan. |
| `NativeCopy` | Writes compile to a native DuckDB `COPY`. |
| `ReplaceWrites` | Supports `strategy: replace`. |
| `BoundedWindow` | Honors an entity's upper watermark bound. |
| `PathTemplating` | Understands calendar tokens in `path`. |

## Notes

- Forcing the universal tier (`engine.force_universal`, or setting `files_per_partition`) fails
  with `PZ0312`: this connector has no universal read or write path at all.
- Any S3-compatible store, not just AWS, is reachable through the `endpoint` override.
